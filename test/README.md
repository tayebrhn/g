# Local authorization checks

Run the database-free authorization regression tests from the repository root:

```powershell
php test/menu_authorization.php
php test/authorization_tiers.php
php test/modify_authority.php
php test/capability_matrix.php
php test/answer_key_visibility.php
php test/answer_key_visibility.php disabled
php test/online_users_tracker_rows.php
php test/login_button_visibility.php
php test/candidate_flow_integrity.php
php test/editor_mutation_authority.php
php test/admin_operations_integrity.php
php test/user_management_integrity.php
php test/role_visibility_matrix.php
php test/test_question_management_integrity.php
php test/test_candidate_exam_ux_integrity.php
```

`menu_authorization.php` verifies the Users, Modules, and Tests landing-page menus for the representative capability masks and for the legacy level fallback: a mask never includes another capability (an OPERATOR-only account sees no content editor, and an EDIT_CONTENT-only account does not unlock the read-only editors). `authorization_tiers.php` verifies that the capability constants are distinct bits, that the visibility/read-only helpers match the masks on every combination, that the content editors cannot be modified without the EDIT_CONTENT capability, and that every mutating page gates changes with the `F_isAuthorizedToModify*()` predicates. `modify_authority.php` stubs the database functions and verifies that the modify predicates accept owner / shared-group / K_PERM_ADMIN access, that a GLOBAL_VIEW user can see a record but not modify it (even at the maximum rank), and that the emailed-results capability token validates only within its time to live. `capability_matrix.php` verifies the legacy level-to-mask mapping, the all-of/any-of semantics of `F_user_can()`, that every admin page declares its capability in `$pageperm` and that the menu entries reference defined capabilities. `answer_key_visibility.php` verifies that the answer key inside the result reports is hidden from unrelated operators, test-takers and anonymous sessions (the emailed-results token path), and visible to the subject owner, a group peer and global-view users; run it with the `disabled` argument to verify the legacy behaviour restored by `K_RESTRICT_ANSWER_KEYS = false`, and note that the renderers are checked by source assertions so they must consult `F_canSeeAnswerKeys()`. `online_users_tracker_rows.php` verifies the online-users visibility guard. `login_button_visibility.php` verifies that the redundant userbar login button is suppressed when viewing authentication screens and that the top menu marks the login page active. `candidate_flow_integrity.php` verifies that candidate-facing results and start pages validate parameters and permissions prior to outputting headers (guaranteeing clean HTTP 302 redirects), validates XHTML textarea attributes, ensures client-side timer null safety, guards keyboard shortcuts against input hijacking during comment entry, and ensures direct completion routing to test results. `editor_mutation_authority.php` verifies that the admin subject, question, and answer editors gate new record creation against unauthorized parent modules and subjects, unpack and synchronize parent IDs to prevent cross-parameter spoofing, enforce read-only states, and maintain defense-in-depth authorization in addition handlers. `admin_operations_integrity.php` verifies that question list bulk actions (move, copy, delete, enable, disable) and toolbar UI elements are gated against unauthorized operators and require modify authority on target subjects, that the free-text rating editor unpacks and synchronizes parent test IDs to prevent cross-test rating attacks while capping scores using server-side database weights, that the SSL certificates editor updates the correct database table on disable and extracts all parameters, and that database backup and restore utilities validate filenames against path traversal, extract request parameters, and enforce read-only content mode. `user_management_integrity.php` verifies that user and group editors extract modern PHP request parameters, enforces rank elevation ceilings and self-edit locks, enforces capability delegation filters and unheld capability preservation, validates account deletion safeguards (blocking self-deletion and anonymous user removal), restricts group modification to owned groups, binds bulk user actions and search filters, and validates client-side smart auto-sync presets between user levels and capabilities with server-side fallbacks. `role_visibility_matrix.php` verifies that `K_PERM_MANAGE_IDENTITY` has inherently global authority to view, edit, and assign all groups and subordinate users across all groups (including unassigned users without groups), verifies that the vertical rank ceiling prevents peer and superior tampering, and verifies that non-identity roles (Content Authors and Examiners) remain strictly contained to their own groups. `test_question_management_integrity.php` verifies that the test editor aggregates question counts in a single grouped query (preventing N+1 query bottlenecks), provides module dropdown filtering and real-time topic search, displays human-readable total question counts in topic options, computes interactive live available question counts based on selected question type and difficulty level with a quick-fill `[use all available]` button, presents configured test subsets in a structured summary table with localized question type descriptions and individual point calculations, supports direct 1-click subset deletion alongside backward-compatible bulk deletion, resets question addition form fields upon successful creation, guards against duplicate submissions on refresh or double clicks via session submission tokens, and synchronizes browser history state via `window.history.replaceState` to prevent POST resubmission prompts on page refresh. `test_candidate_exam_ux_integrity.php` verifies the modernized candidate exam execution interface: option letter badges (A, B, C, D) and full-card descriptions, clean single-answer deselect control (`FJ_clear_selection`), compact responsive Question Palette grid with color-coded status chips (answered, unanswered, current, flagged) and header counters while preserving native form submission jumping (`jumpquestion_X`) and backward-compatible hidden question menus, client-side and session-persisted "Flag for Review" bookmarking, sticky exam status header featuring live progress bar tracking (`X / Y Answered (%)`) and smart timer urgency alerts (amber warning < 5m, pulsing red critical alert < 1m), and the pre-submission review modal and confirmation screen providing categorized breakdown cards and direct jump buttons for missed and flagged questions. None of the tests creates accounts, authenticates, or modifies the database.

The admin PDF/XML export endpoints are also required to pass their configured page-level authorization checks; direct anonymous requests must receive the authentication page.

For a browser-based local check, use a non-production database, run the upgrade SQL first, and create separate accounts with the following capability masks (the rank can be set freely, it grants no right). Verify that:

- an account without capabilities reaches no admin page and sees no admin link in the public area;
- VIEW_CONTENT only opens the Modules editors without any update/add/delete button and rejects a forced `menu_mode` submission;
- EDIT_CONTENT only reaches the question importer and the file manager but not the editors nor the question list;
- OPERATOR only reaches the Tests section and the question list, and nothing else;
- MANAGE_IDENTITY only reaches the Users section, and only lists the users of the same groups with a lower rank;
- GLOBAL_VIEW sees the data of every group in read mode, but the editors show no update/add/delete buttons on records it does not own and reject a forced `menu_mode` submission;
- BACKUP only reaches the backup page;
- ADMIN only reaches the system update page, the owner reassignment selects and the file-manager root; it does NOT open the content or users pages unless the matching capabilities are also granted;
- only an account holding a capability may grant it, and the capabilities of a user edited by a lesser administrator are preserved;
- removing a capability or an account takes effect on the current session immediately (no re-login required);
- an operator who owns a test assembled from another author's questions opens the report but sees no right/wrong mark, no correct ordering and no explanation, while the test-taker's own report never shows the correct answers; linking the operator to a group shared with the author reveals the key on the next request, without re-login, and `K_RESTRICT_ANSWER_KEYS = false` restores the key for everyone;
- migrating a level-based database preserves everyone's rights exactly (see UPGRADE.TXT).

Do not use default or shared credentials.
